# Evidence and execution limits

This fills the gap between RCA hypotheses and approved control evaluation: accountable draft proposals. Existing RCA supplies assessment/provenance and local provider code; Monitor handles population aggregates; Control Validation handles approved pilots and outcome evaluation. No new connector or SQL engine is introduced. The shared normalizer uses the existing workflow schema with a mock fetch callback; the `postgres` source kind labels schema compatibility, not a database connection.

Accepted inputs are fixed synthetic IDs and enumerated administrative events/queues/exception categories. No raw message field, patient field or clinical data exists. Exception labels are recorded assertions, not independently detected missing acknowledgments. A completeness flag covers the selected snapshot, not a verified source inventory. Missing selected cases, duplicate IDs, equal timestamps within a case, out-of-window rows or incomplete coverage suppress all evidence for inquiry. Delayed delivery, clock uncertainty and off-system activity are not modeled beyond that completeness assertion; set it false whenever unresolved. No durations or latest-state conclusions are inferred.

Budgets: up to ten cases over seven days, forty events, 16,000 serialized evidence bytes, one-MB JSON input files, existing 100,000-byte response validator and 250,000-byte combined output limit. Oversize evidence fails instead of silently truncating for the model. Existing local context/output limits are unchanged. These bound request size, not model weights or peak RAM/VRAM. Model loading, server concurrency, keep-alive and runtime memory remain operator responsibilities; no hardware profile has been benchmarked. A non-streamed SDK response may be allocated before post-response byte validation, and a server may ignore requested generation limits. Timeout is not proof that server computation stopped.

The local and host paths both receive trusted pharmacy administrative restrictions above untrusted evidence. Validation verifies packet hashes, exact quotes, distinct hypothesis text, evidence presence, schema and some sensitive patterns; it does not certify semantic entailment, distinct causal mechanisms, clinical-domain compliance, sound controls, role authority or model accuracy. Human review must reject unsafe/unsupported output. Hashes bind content, not authenticity. Synthetic labels do not prove all prose is free of sensitive content; never supply real information.

Accountability records are a human-authored draft: one role/deadline/closure requirement per proposed control and links to non-rejected hypotheses. An unknown hypothesis can justify a proposal to investigate, not implementation. No approval, implementation status, outcome estimate or action completion is inferred. Generated prose may be incorrect even when citations pass. No external actions, clinical decisions, model tools, automatic RCA/validation execution, schedules or notifications exist.

Only synthetic fixtures and mocked Ollama responses were tested. No real model availability, latency, memory use, accuracy, instruction resistance, local-server privacy configuration or live service behavior was validated. The workflow makes no claims about any real employer's infrastructure or required operating procedures.
