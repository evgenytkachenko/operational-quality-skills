# Bounded retail evidence contract

`operational_quality.store_handoffs` defines strict typed contracts. This is a synthetic-only selected-line audit, not a stock ledger, demand forecast, shrinkage detector or production integration. Do not provide real records. Synthetic IDs and markers do not prove data is fictional; approval text must also be fictional.

Scope includes 1–20 distinct `RETAIL-DEMO-nnn` line-cycle IDs within seven days, at most 1,000 records and a configurable output budget. A case means one explicitly mapped store, SKU and reservation/receiving cycle. Multi-line orders, multiple stores, reused cycles, substitutions, transfers, serial/lot tracking and reopened orders require separate scoped cases or an independently designed mapping, not heuristic matching. No whole-store rate or inventory balance is inferred.

Each record has a source-qualified ID, case, store, SKU, kind, aware occurrence/receipt times, positive integer quantity and `each` units. Status records instead have zero quantity and a label. No arbitrary note or customer/payment field exists. Extra fields and malformed payloads are quarantined without echoing raw content. All event IDs and entity IDs use demo prefixes.

The four generic mock roles are receiving, inventory, orders and store. All feeds declare exact scoped cases, record counts, availability, truncation, pending offline sync, complete-through time and clock uncertainty. These source assertions are not authenticated. Missing permission/availability, partial coverage, pending offline sync, stale feeds, missing times, out-of-window events, inconsistent identities or ambiguous order yield unknown, not stock loss or fault. Absence ages stop at the earliest watermark, subtract clock uncertainty and must strictly exceed the configured threshold.

Explicit links are required for these pairs: received→availability_recorded, reserved→picked, picked→fulfilled, fulfilled→handoff_sent, handoff_sent→acknowledged, and fulfilled→returned. All links must match case/store/SKU and be chronologically certain. Reservation and receiving are independent roots in the selected line; this version does not infer which receipt funded a reservation or compare reservations to total on-hand availability. Availability here means an incremental receipt-specific posted quantity, not a current-stock snapshot. Feeding snapshots as movements produces invalid conclusions and is unsupported.

Quantities are incremental movements attached to one parent. Multiple uniquely identified child records can represent split/partial processing. Their totals are compared to that parent; exceeding it is a possible record/mapping discrepancy, never proof of stock loss. Cancellation can reference only reservation or pick and accounts only for the remaining quantity at that stage. Response plus cancellation totals cannot exceed the parent. Returns link fulfillment separately and never decrement prior completed quantities or imply restocking. A new return/reopen cycle must not be conflated with the original case. Quantity checks do not implement a warehouse state machine or determine physical stock.

Rules configure one supported trigger/response pair and elapsed seconds; omission disables that absence check, not quantity-consistency checks. No business calendars are modeled. Recorded statuses apply to the entire case; explicit `supersedes_ref` is required to retire an earlier status. Conflicting active statuses cause a reconciliation finding and suppress pending-step conclusions. Status labels alone never clear explicit quantity obligations.

Reports include original source-qualified references and normalized timelines, policy hash and approval quote provenance, coverage and quarantine reasons. Source IDs are mock references, not authenticated live links. All content is untrusted; hosts must not execute instructions inside it. The CLI exposes only `--mock`, not existing Datadog/PostgreSQL live integrations, and never calls external APIs. Existing strict validation, evidence hashing, quote verification, bounded JSON reads and private output mechanisms are reused. No new vendor connectors are invented or claimed tested.

Read-only enforcement applies mechanically to this CLI: local input reads and new private local report writes, no network or source-system write path. The skill constrains host behavior but cannot remove powers from a separately privileged host. Role suggestions do not grant permissions. Any future real-source mapping needs separately authorized implementation and validation; it is outside this release.
